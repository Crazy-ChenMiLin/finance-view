🛡️ 核心系统 12 道业务防线与硬门禁规则矩阵 (System Invariants)

防线编号 防御机制名称 承载模块 / 服务 门禁类型 触发场景与拦截规则 审计状态
G-01 跨库预算超标硬拦截 srv-purchase-pr 硬拦截 (Warn) 穿透查询 PM 独立库 projects 表，金额超出可用预算时阻断审批发起 PASS
G-02 未建档项目隐式放行 srv-purchase-pr 软放行 (Unknown) 项目库未建档时标记 status=unknown，保障应急采购不被系统卡死 PASS
G-03 试用期供应商限额封顶 srv-purchase-po 硬拦截 (20W) 试用期供应商自然年度内累计采购订单金额不得超过 20 万元整 PASS
G-04 历史均价 10% 偏离预警 srv-purchase-po 预警 (Alert) 物料报价与过去半年同物料历史均价偏离超过 ±10% 时触发人工复核 PASS
G-05 PO 分摊尾差吸收算法 srv-purchase-plan 算法保真 供应商成交总价按 PR 明细占比分摊，尾行自动吃掉分币尾差，账实绝对相符 PASS
G-06 采购合同金额阶梯审批 srv-purchase-contract 权限矩阵 <2W免签 / 2-5W部长与副总审批 / ≥5W总经理逐级审批 PASS
G-07 验收单四道严苛门禁 srv-purchase-accept 四重门禁 必须同时满足：PR已审批 + 计划已生效 + PO已确认 + PO未被强制关闭 PASS
G-08 发票三单匹配核验 srv-purchase-invoice 三单校验 PO 含税单价、合同约定付款条款与验收实际到货数量三单对齐后方可入账 PASS
G-09 发票联合唯一索引防重 srv-purchase-invoice 唯一约束 数据库 UNIQUE KEY (invoice_code, invoice_no) 物理防重报销入账 PASS
G-10 非预付款必须有验收发票 srv-purchase-payment 资金防线 非预付款类型的资金提报，必须挂接审批通过的验收单与合规发票，防超付 PASS
G-11 移动端扫码防重放锁 srv-signature-session Redlock分布式锁 Redis Session Token 600s TTL 超时；提交签名加分布式锁，防跨端重写 PASS
G-12 WPS 正文不可篡改归档 srv-doc-pipeline 防篡改文档 签名图注入 Word 书签后，直接调用底层转换引擎输出不可篡改 PDF/A 归档 COS PASS

● CI/CD Deployed

📄 GitHub Actions 工作流配置 (.github/workflows/living-architecture.yml)：

name: Living Architecture CI/CD

on:
  push:
    branches: [ main ]
  schedule:
    - cron: '0 3,9,15,21 * * *'
  workflow_dispatch:

permissions:
  contents: write
  pages: write
  id-token: write

jobs:
  check-and-deploy:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm install --production=false
      - run: node scripts/build-site.js
      - run: node -e "require('./scripts/security-sanitizer').sanitizeAndVerifyDirectory('./dist')"
      - uses: actions/configure-pages@v4
      - uses: actions/upload-pages-artifact@v3
        with:
          path: './dist'
      - uses: actions/deploy-pages@v4
